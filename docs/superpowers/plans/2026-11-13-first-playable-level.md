# 首关可玩原型实现计划

> 面向实现者：按清单逐项完成。目标是一个可在移动浏览器操作的首关原型；iOS 真机打包需在 macOS/Xcode 上完成。

**目标：** 做出包含三类别轮换、覆盖判定、临时格、口令解锁、撤回、自动存档和可拖动场景的首关，并为后续六关建立同一数据格式。

**架构：** TypeScript 游戏规则不依赖渲染器；Phaser 负责场景绘制、镜头拖动和物品命中；HTML 控件负责固定顶部界面、口令输入和音乐文件选择。关卡数据描述类别、物品位置和覆盖关系，不在渲染代码中硬编码关卡。

**技术栈：** Vite、TypeScript、Phaser、Vitest；iOS 阶段使用 Capacitor。依赖版本由实际安装时生成的 lockfile 固定。

**当前环境：** Windows，Node.js v20.20.2；未发现 Swift/Xcode。当前 Capacitor 环境文档要求 Node.js 22 及 macOS/Xcode 才能进行 iOS 构建，因此第 6 项的 iOS 验证需要更换或补充环境。

**依据：** [已确认的七关设计](../../level-design-draft.md)。Phaser 官方文档：https://docs.phaser.io/ 。Capacitor iOS 文档：https://capacitorjs.com/docs/ios 。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/game/model.ts` | 游戏状态、点击、类别轮换、临时格、撤回与重试 |
| `src/game/level.ts` | 关卡数据结构、数量与覆盖关系校验 |
| `src/game/scene.ts` | Phaser 场景、摄像机拖动、物品可点状态和渲染 |
| `src/game/save.ts` | 本地存档的读写与版本检查 |
| `src/audio/music.ts` | 默认音乐、本地导入、音量与静音 |
| `src/ui/hud.ts` | 固定的三个类别框、临时格、对话框和设置入口 |
| `src/levels/level1.ts` | 顶楼阳台的 8 类、50 件物品数据 |
| `tests/model.test.ts` | 类别轮换、暂存自动结算、满格、撤回和重试 |
| `tests/level.test.ts` | 关卡配额、覆盖图和可解性检查 |

## 任务 1：建立可运行项目

- [ ] 用 Vite TypeScript 模板创建项目并安装 Phaser、Vitest；保留 `docs/`，不要覆盖已有设计文档。
- [ ] 加入 `dev`、`build`、`test` 脚本。运行 `npm run build` 与 `npm test`，确认空项目可构建。
- [ ] 创建竖屏游戏容器和固定顶部界面容器。浏览器视口改变时，场景区域填满剩余空间，不出现横向页面滚动。

## 任务 2：实现纯规则模型

- [ ] 定义 `Level`：有序类别数组、各类别目标数、物品实例数组；每个实例含稳定 ID、类别 ID、位置、尺寸和 `coveredBy` ID 数组。
- [ ] 定义 `GameState`：已取物品 ID、三个可见类别槽、下一类别索引、各类别计数、临时格物品 ID、已开放格数、撤回历史和失败/通关状态。
- [ ] 先测试后实现 `pick(itemId)`：被覆盖物品无变化；可见类别直接计数；未显示类别进临时格；达标后仅替换所属类别槽，再自动结算新类别的暂存物品。
- [ ] 先测试后实现满格、口令解锁、一次撤回、重试和通关。撤回必须原子恢复一次点击连带的类别轮换和自动结算。
- [ ] 验证口令只作用于请求的操作；第 6 至第 10 格按次开放，重试或新关卡恢复五格。

## 任务 3：关卡数据与可解性

- [ ] 校验类别数、类别配额之和、物品 ID 唯一性、类别归属、坐标范围、覆盖引用和覆盖图无环。
- [ ] 为首关布置 50 件物品，类别配额依次为 `6,6,6,6,6,6,7,7`。每件物品使用独立实例 ID；画稿允许复用。
- [ ] 用规则模型搜索首关通关路径：从五格起步，不依赖口令解锁或撤回。若无解，调整具体覆盖关系，不放宽规则。
- [ ] 后续六关按同一校验器逐关制作；其类别/物品总数依次为 `9/80, 10/120, 11/180, 12/270, 13/297, 14/327`。

## 任务 4：场景与固定界面

- [ ] 绘制独立于参考截图的顶楼阳台背景与可交互物品图。物品轮廓命中区应与视觉形状相符；全部被压住时禁用点击。
- [ ] 实现上下左右拖动场景，顶部三个类别框与临时格固定。短按拾取与拖动平移使用同一手势判定，拖动结束不得误拾取。
- [ ] 完成类别进度、格子占用、满格弹窗、解锁、撤回、重试及通关界面。
- [ ] 在窄屏手机视口检查：文字不溢出，格子扩至十个后仍能操作，场景边缘不会拖出空白区域。

## 任务 5：存档与音乐

- [ ] 在每次有效操作后保存关卡状态、撤回历史、开放格数和镜头位置；刷新或关闭后能继续。仅主动重试清空本关状态。
- [ ] 提供默认背景音乐、从本地文件导入、音量和静音；保存音乐设置及所选文件。导入失败时保留当前音乐并显示错误。
- [ ] 浏览器页面失去焦点时暂停播放，恢复焦点后遵守静音设置。iOS 音频中断与文件持久化需在真机验证。

## 任务 6：验证与 iOS 交接

- [ ] 运行规则测试、关卡校验、生产构建；在桌面和手机尺寸浏览器检查拖动、点击、满格、撤回、存档及音乐导入。
- [ ] 记录首关在无额外格数下的实际通关路径，并用自动化回放；确认 50 件全被移除才通关。
- [ ] 将 Node.js 升级到 Capacitor 要求的版本；在 macOS 上添加 Capacitor iOS 平台，用 Xcode 构建并在真机验证性能、触控、音频导入、后台恢复和本地存档。当前 Windows 工作区不能完成此项。

## 首关验收

玩家能在一张可四向拖动的顶楼阳台中找完 8 类、50 件物品；顶部同时显示三类，达标后只替换对应框；临时格、口令、撤回和重试符合规则；刷新后进度仍在。首关固定布局经过五格通关路径验证。其余六关作为后续内容生产阶段逐关加入并使用相同验收。
